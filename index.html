Autonomous agents create a new attack surface

Coding agents use MCP servers to read files, run shell commands, and hit the network. If an agent ingests untrusted content — a webpage, a repo file, a database row — containing a hidden prompt injection, it can be manipulated into running destructive commands or exfiltrating secrets, using your own valid credentials. Static-analysis tools and network firewalls are both blind to this: neither operates at the live protocol layer where the agent and its tools actually talk to each other. Aran sits inline at that layer instead.

How it works

Four things happen automatically, for every MCP server you wrap.

01

Drop-in, not a rewrite

Wrap the command you already use to launch an MCP server. No server-side changes, no new protocol to learn, no code for the downstream server to adopt.

02

Destructive calls never execute

Every outbound tool call is checked against destructive-command signatures — rm -rf, chmod 777, fork bombs — before it reaches the real server. A match never leaves the proxy.

03

Injected content never reaches your agent

Every inbound response is scanned for prompt-injection signatures. A match is redacted before relaying — the agent's context window never sees the raw payload.

04

A full audit trail, always local

Every gated call — allowed or blocked — is logged to ~/.aran/audit.jsonl. Nothing is sent anywhere; the log never leaves your machine.

Install in your IDE

Pick your agent. Every path below wraps the same proxy — nothing about the downstream MCP server changes.

One-time setup required first

Aran isn't on PyPI yet, so the button/config below configure your IDE correctly, but the server will show as errored until the aran package itself is installed. Run this once, in any terminal:

git clone https://github.com/aranaisec-cyber/aran.git
cd aran
pip install -e .

Once published to PyPI, this step goes away entirely — uvx will fetch Aran automatically, the same way it already does for the fetch server below.

One click installs aran-fetch — Aran wrapping the official MCP fetch server — directly into Cursor.

Add to Cursor

Requires uv installed. Wrapping your own server instead is a one-line config change — see the docs.

Prefer to edit config directly? Add this to .cursor/mcp.json:

{
  "mcpServers": {
    "aran-fetch": {
      "command": "python",
      "args": ["-m", "aran.cli", "--", "uvx", "mcp-server-fetch"]
    }
  }
}

Run this once — it writes the config for you:

claude mcp add aran-fetch --scope user -- python -m aran.cli -- uvx mcp-server-fetch

Or use the in-chat /mcp command, or clone the repo — it ships a working .mcp.json that Claude Code auto-detects with a one-time approval prompt.

View .mcp.json in the repo

Any MCP-speaking client that reads a command/args config works the same way — wrap the launch command with aran --:

# install
pip install aran

# wrap any MCP stdio server
aran -- npx -y @modelcontextprotocol/server-filesystem /path/to/project

Built to be trusted, not just used

Aran is early — v0.1, pre-1.0 — and we'd rather tell you exactly what that means than oversell it. Here's what's actually true today.

100% local, zero telemetry

Aran runs as a subprocess on your machine. The audit log is a plain file on disk. Nothing is sent to us — we couldn't see your traffic if we wanted to.

Open source, MIT licensed

Every line that touches your traffic is on GitHub. Read it, fork it, audit it before you trust it — that's the point.

Tested against a hostile server

Not just a cooperative test fixture — a dedicated adversarial server (colliding request ids, malformed shapes, batch framing, bad encodings) exercises the gates the way a compromised server actually would.

Fail-closed by design

Redaction defaults to on; only a short, explicit list of protocol-machinery fields is exempt. An unrecognized message shape doesn't get a free pass — it gets gated.

165 automated tests

Including real subprocess integration tests, not mocks — the CLI, the proxy, and the packaged wheel are all verified before every release.

Responsible disclosure

Found a gate bypass? We have a private reporting path and a documented response process — see SECURITY.md.

Frequently asked questions

What MCP servers does Aran work with?

Any MCP server that speaks the stdio transport — which is most of them. You wrap the exact command you'd normally use to launch it; nothing about the server changes.

Does it support remote/HTTP MCP servers?

Not yet. v1 is scoped to stdio servers specifically. It's an explicit, documented scope boundary — not something we're hiding.

Does it slow down normal tool calls?

Clean calls pass straight through. Signatures are compiled once at startup, not per-call, specifically to keep the gating overhead negligible.

What if it flags something benign (a false positive)?

Every match is logged with the exact signature that fired, in ~/.aran/audit.jsonl. Report it and we'll tune the ruleset — see CONTRIBUTING.md for the process.

Is any of my data sent to Aran's maintainers?

No. Aran runs entirely on your machine as a local subprocess. There is no phone-home, no telemetry, no account required.

Is Aran production-ready?

It's early (v0.1, pre-1.0). The core proxy is implemented and hardened through several rounds of adversarial security review — but we'd rather you read the code and the test suite than take our word for it.
