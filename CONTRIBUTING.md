# Contributing to Aran

Thanks for considering a contribution. This project gates untrusted content
before it reaches an AI agent or a developer's machine, so correctness bugs
here are security bugs — see [SECURITY.md](SECURITY.md) before filing a
vulnerability as a regular issue.

## Development setup

```bash
git clone <this repo>
cd mcp_shield
pip install -e ".[dev]"
pytest
```

Requires Python 3.10+.

## Project layout

- `src/mcp_shield/rules.py` — loads gate signatures from
  `src/mcp_shield/default-rules.yaml`, with fail-safe defaults if the file
  is missing or malformed.
- `src/mcp_shield/gates.py` — regex signature matching (`check_output` for
  outbound tool calls, `check_input` for inbound tool results).
- `src/mcp_shield/audit.py` — thread-safe JSONL audit logging.
- `src/mcp_shield/proxy.py` — the core: spawns the wrapped MCP server,
  relays JSON-RPC on two threads, and applies the gates. This is the file
  that matters most for security review.
- `src/mcp_shield/cli.py` — the `aran` command-line entry point.
- `scripts/sync_threat_intel.py` — regenerates
  `src/mcp_shield/default-rules.yaml` from a labeled public dataset.

## Testing philosophy

This codebase treats the wrapped downstream MCP server as **untrusted
input**. `tests/fixtures/fake_server.py` is a cooperative test server;
`tests/fixtures/hostile_server.py` is adversarial (malformed shapes,
colliding request ids, batch framing, bad encodings) and is what most of
`tests/test_proxy_hostile.py` drives `run_proxy` against, using real
subprocesses rather than mocks. If you're fixing or extending gating logic,
a hostile-server test demonstrating the specific bypass/behavior is the
expected form of coverage, not just a unit test against a cooperative peer.

Run the full suite before opening a PR:

```bash
pytest -v
```

## Reporting signature false positives

If a signature in `src/mcp_shield/default-rules.yaml` is redacting benign
content, please open an issue with the offending signature and a sample of
the text it matched. This file is machine-generated by
`scripts/sync_threat_intel.py` from a labeled public dataset, so systematic
false-positive patterns are worth fixing upstream in that script (e.g. a
minimum-length or specificity threshold) rather than hand-editing the
generated YAML.

## Pull requests

- Keep PRs focused — one fix or feature per PR.
- Add or update tests for any behavior change, especially in `proxy.py`,
  `gates.py`, or `rules.py`.
- Explain *why*, not just *what*, in the PR description if the change
  affects gating/security behavior.
